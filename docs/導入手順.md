# 導入手順（約30分）

> β版です。手順どおりに進めば、Vault の配置から最初の日記まで完了します。
>
> - **もっとやさしい説明が必要な方へ**: 同じ内容を「なぜ」と「困ったとき」つきで丁寧に書いた `docs/親のための完全導入マニュアル.md` があります。パソコンに不慣れな方はそちらから
> - AI エージェント（Claude 等）と一緒に進めることを推奨します。各ステップは AI に「導入手順の Step N をやって」と頼めば実行できます
> - **導入が終われば、親がすることは「今日こんなことがあった」と AI に話すことだけ**です。ファイル操作も Markdown も要りません（記入経路の原則は schema.md §0-1）

## Step 1. Vault の配置と公開への道の遮断（5分）

1. このリポジトリを clone するか ZIP でダウンロードし、Obsidian の Vault として開きます（例: `~/Obsidian/oya-iru-wiki/`）
2. **実データの運用を始める前に**、公開 remote への push 経路を断ちます: clone した場合は `git remote remove origin`、または private リポジトリに切り替え。`.gitignore` が raw/（日記を含む）を除外しますが、構造的防御を二重にするためです
   - pre-commit の関所2 がこれを機械的に見張ります。**remote があり、かつ個人に紐づくページ（persons / koe / sentaku / fushime / trials / protocols / triggers / ecomaps / sensitive）が存在する状態でのコミットは止まります**。テンプレートを取ってきただけの段階（個人ページ0件）では止まりません
3. ZIP でダウンロードした場合、実行権限が落ちていることがあります。`chmod 755 githooks/pre-commit scripts/*.py` で戻してください（非実行のままだと関所が黙って無効化されます）

## Step 2. lint の初回実行と関所の有効化（2分）

```bash
cd <あなたのVault> && python3 scripts/okf_lint.py
```

依存パッケージなし（Python3 標準ライブラリのみ）。「違反なし」が出れば骨格は健全です。あわせて pre-commit 関所を有効化します:

```bash
git config core.hooksPath githooks
```

## Step 3. AI の用意 — 選ぶ・確かめる・つなぐ（10分）

この Vault は特定の AI を前提にしません（指示書の正典は `AGENTS.md`。`CLAUDE.md`・`GEMINI.md` はそこへの案内板です）。動作確認済みの AI は README の表を参照してください（参照実装は Claude）。

**3-1. AI 選択時のチェックリスト（機微情報の観点・必須）**

日記には子どもの発達・健康・行動など、最も繊細な個人情報が含まれます。使う AI について、契約前に次を確認してください:

- [ ] **入力内容が AI の学習に使われない**こと（学習オプトアウトの設定、または学習に使わないプラン・規約であること）。無料プランは入力がサービス改善に使われうるものが多く、**この用途には使えません**
- [ ] データの保持期間・削除の方法が示されていること
- [ ] Vault のフォルダを読み書きできること（AGENTS.md §0 の AI 要件: ファイル読み書き／日本語／lint 実行／承認ゲートの尊重）
- [ ] ローカル LLM を使う場合: 情報は外に出ませんが、この Vault での品質は未検証です

**3-2. AI に Vault と受付箱を見せる**

1. **受付箱を作ります。** Vault の**外**に、園・学校の書類などをいったん置くフォルダを1つ作ってください（例: `~/Desktop/受付箱`）。日記はここを通りません（チャットで話すだけ）——受付箱は**書類の**入口です
2. AI のファイルアクセス設定（filesystem MCP 等）に **この Vault と受付箱** の2つを指定します。この設定は最初の1回きりです
3. つながったか確認: AI に「Vault の raw の下に棚がいくつあるか教えて」と聞き、**「8つ」**と返れば成功です

> **なぜ受付箱を Vault の外に作るのか。** 受け取った書類はまずここに置き、AI が中身を仕分けて原本を `raw/` の棚へ移します（移動なので、済めば受付箱は空に戻ります）。`raw/` は追記専用で、入れたら書き換えも削除もできません。手前に一段あることで、置き間違いを記録される前に取り消せます。

**3-3. 起動時ゲートの確認**

新しいセッションで AI が最初に `python3 scripts/okf_lint.py --gate` を実行することを確認してください（AGENTS.md §5。ERROR があると作業に入る前に報告されます）。

## Step 4. 子どもの登録（5分）

AI にこう頼んでください:

> 「子どもの記録を始めたい。名前は◯◯、生まれは◯年◯月」

AI が次を行います（親がファイルを作る必要はありません）:

1. `wiki/persons/P_001_◯◯.md` を作成（実名は raw/ のみ、wiki/ は P_001 形式の原則に従って）
2. `docs/年齢イベント表.md` の登録欄に生年月を記入し、**次の12ヶ月に窓が開く制度イベント**（就学相談・手帳の再判定・18歳・20歳 等）を一覧にして見せる

## Step 5. 定期 ingest のスケジュール登録（5分）

日記や書類を wiki に編み込む作業（ingest）は **AI が定期的に行います**（既定は月次）。自動で起動する仕掛けを、環境に合わせて1つ登録してください:

| 環境 | レシピ |
|------|--------|
| **スケジュール実行機能のある AI**（例: Claude のスケジュールタスク） | 「毎月1日に、AGENTS.md §3-1 の定期 ingest を実行して」を登録 |
| **CLI エージェント**（`claude -p`・`gemini`・`codex exec` 等が使える方） | cron / launchd で月次起動（例: `0 9 1 * *` で毎月1日 9:00 に「AGENTS.md に従い定期 ingest を実行」を実行） |
| **自動化できない環境** | カレンダーに毎月1日の繰り返しリマインダー「AI に『取り込んで』と頼む」を登録（手動フォールバック。これで十分に運用できます） |

いずれの環境でも、親が「取り込んで」とチャットで頼めばいつでも手動 ingest できます。

## Step 6. 最初の日記（3分）

準備は完了です。AI にこう話しかけてください:

> 「今日こんなことがあった。◯◯◯◯」

AI が「あったこと（事実）」と「おもったこと（親の思い）」を聞き分けて、今月の日記ファイルへの追記を宣言し、あなたの承認を得てから書き込みます。**1行でかまいません。「今日は何もなかった」も記録です。**

書きぶりのイメージは `記入例/` にあります（最初に `記入例/0_この記入例について.md` を読んでください——**親が作るファイルは一つもない**ことが分かります）。記入例が不要になったらフォルダごと削除できます。

## 任意: 制度ウォッチの起動（あとからで可）

`docs/watchlist.md` が制度改正の監視台帳です。余裕が出てから、①あなたの自治体の障害福祉ページを §2 の地域枠に登録（AI に「◯◯市の障害福祉のページを watchlist に登録して」と頼めます）、②監視ツールがあれば §1 の手順で登録してください。使わなくても日記の運用はできます。

## AI なしでも止まらない（手動運用の下限）

AI は加速装置であって前提条件ではありません。AI が使えない期間も、次の下限で運用は続きます:

- **日記**: `templates/日記.md` の形（`## 日付` と「あったこと」「おもったこと」の2欄）で、当月ファイルに自分で書き足す
- **書類**: 受付箱に溜めておく（仕分けは AI が使えるようになってからで可）
- **wiki への編み込み**: `templates/` と `記入例/` を見て人手で書くこともできます。書いたら `python3 scripts/okf_lint.py` で検査してください（機械検査は AI に依存しません）

## 困ったとき

- lint が ERROR を出す → 出力メッセージが対処を書いています。ERROR は機微情報の漏出リスクなので、解消するまで commit されません（fail-closed）
- コミットが関所で止まる → 出力を AI に貼れば原因を説明します。関所が何も言わず素通りする場合は Step 1-3 の `chmod` を実行
- 過去の月の日記を直したくなった → 月が変わった日記は凍結です（schema.md §0-3）。今月の日記に「◯月◯日の件、実は…」と書くのが正しい訂正の形です
- エラーの文字が出た → 意味を考える前に、そのまま AI に貼ってください

## この版で確かめてあること・いないこと

- **確かめてある**: ページの型・必須項目・機微情報の扱いが機械検査を通ること。「通らなかった」の理由が欠けたら止まること（実際に壊して確認）。本手順の Step 1〜2 と Step 4 以降の機械部分が新しい環境で再現できること
- **確かめていない**: 書きぶりが子育ての実感に合うか。日記→月次 ingest のリズムが実生活で回るか

**仕組みは検証済み・実務適合は未検証**です。使ってみて違和感があれば、それはあなたが正しい可能性が高いです。お知らせいただけると助かります。
