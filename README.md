# oya-iru-wiki — 親がいる「今」から、日記で育てる意思決定支援のバイブル

> **β版です。** 本テンプレートは骨格と検査機構を配布しています。構造・検査ルールは実運用の学びで更新されます。
>
> **そして、はっきりお伝えしておきます。仕組みは検証済みですが、実務適合は未検証です。**
> ページの型・必須項目・機微情報の扱いが機械検査を通ること、必須項目が欠けたら止まることは、架空の子ども2名で実際に確かめました（壊して止まることも確認済み）。導入手順が新しい環境で再現できることも機械的に検証済みです。しかし**書きぶりが子育ての実感に合うか、日記→月次整理のリズムが実生活で回るか**は確かめられていません。当事者の親御さん・意思決定支援者によるレビューを経て育てていきます。**使ってみて「ここは違う」と感じたら、そちらが正解です。**

## これは何か

**知的障害（自閉スペクトラム症を含む）のある子を育てる親が、親がいる「今」から日記のように子育てを記録し、その積み重ねを、本人に関することは本人が決めることを支える人たち（意思決定支援者）のバイブルに育てるための Obsidian Vault テンプレート**です。

親には「うちの子は、こうすれば伝わる」という、書類のどこにも載らない膨大な知恵があります。このテンプレートは、それを日記という一番小さな単位で受け取り、AI が整理して、いつか本人の隣に立つ誰かが読める形に編んでいきます。

**親に求めるのは日記だけ。それも AI に「今日こんなことがあった」と話すだけです。** ファイル操作も Markdown の知識も要りません（書式を守るのは AI の仕事です）。構造化——選択の場面の抽出、意思表出プロファイルの起草——は AI が定期的に行います。

## 何が積み上がるか

- **こえ**（意思表出プロファイル）— 本人が「はい・いいえ・嫌」をどう表すか。誤読されやすいサインは何か。**バイブルの心臓**
- **せんたく**（選択の記録）— 幼児期の「おやつの二択」から成人期の「住まいの選択」まで同じ型で貫く。本人の希望が**通らなかった記録**は理由必須で残り、後の支援者の検証素材になる
- **ふしめ**（節目の記録）— 就学・卒業・18歳。何を比べ、何を諦め、本人がどう関わったかの判断過程
- ほかに、ためしたこと（失敗の記録こそ一級市民）・手順書・きっかけ など計15型

第一の書式規律はひとつだけ——**「あったこと（事実）」と「おもったこと（親の思い）」を分けて受け取る**こと。親の思いが本人の事実として記録されることを防ぎ、同時に、思いは検閲なしに書ける場所を持ちます（`purpose.md` A-10）。

## 3層構造（OKF）

1. **宣言** — `schema.md` がページ型・必須項目・機微区分・鮮度ルールを宣言する
2. **検証** — `scripts/okf_lint.py` が宣言との乖離を機械検査する（依存ゼロ・Python3 標準ライブラリのみ）
3. **強制** — `githooks/pre-commit` と AI の起動時ゲートが ERROR を通さない（fail-closed)

特徴:

- **日記は raw/10_日記/ の月次ファイル・2欄書式**。書いた月のうちは編集可、月が変わったら凍結（ハッシュ台帳で機械検査）。過去の観察は、後から見れば間違いでも、その時点の記録として守られる
- **実名は raw/ のみ**。wiki/ は `P_001` 形式で仮名化し、lint が混入を検査。書類の入口は Vault の外の**受付箱**1つ
- **鮮度モデル** — 子どもは大人より速く変わる。「現在を主張するページ」には確認日（`last_confirmed`）と賞味期限があり、確かめていないのに更新しない
- **制度ウォッチ＋年齢イベント表** — `docs/watchlist.md` が「外の変化（制度改正）」を、`docs/年齢イベント表.md` が「本人の時間（何歳で何が来るか）」を見張る。**機械は通知まで、判断は親**
- 機微情報（性・行動・きょうだい児）は sensitivity 4段階と記述原則で正面から扱う。判定基準は「**成人した20年後の本人の前で読み上げて恥ずかしくないか**」

## まず見てほしいもの — `記入例/`

架空の子ども2名（P_900 そら・5歳／P_901 かえで・16歳）の記録が丸ごと入っています。まず `記入例/0_この記入例について.md` を読んでください——**たくさんのファイルのうち、親が作ったものは一つもない**（すべて AI が日記から編んだもの）ことが分かります。中核は `日記と資料の例/` の日記2ヶ月分と `仕分け宣言.md`：日記の2欄が別々の行き先を持つ様子が、この記入例の心臓です。不要になったらフォルダごと削除できます。

## 導入

- はじめての方・パソコンに不慣れな方: **`docs/親のための完全導入マニュアル.md`**（「なぜ必要か」と困ったときの対処つき。導入作業そのものを AI に手伝ってもらう進め方も載せています）
- 手順だけ短く: `docs/導入手順.md`（約30分）

## AI について — 特定の AI に縛られない設計

AI への指示書の正典は **`AGENTS.md`**（ベンダー中立）です。`CLAUDE.md`・`GEMINI.md` は AGENTS.md へ誘導する1行シムです。安全装置（lint・関所）は AI 非依存で、どの AI が書いたページも同じ基準で fail-closed 検査されます。

スキル対応のエージェント（Claude Code・Codex CLI など）向けに、`.claude/skills/` と `.codex/skills/` へ薄いスキル3つ（取り込み ingest／照会 query／点検 lint）を同梱しています。中身は AGENTS.md の該当節へ誘導するだけの着火装置で、手順の正典は AGENTS.md のままです。スキル非対応の環境では単に無視されます。
